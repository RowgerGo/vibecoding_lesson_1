# 招聘平台需求确认记录

状态：用户于 2026-10-27 确认最终范围；当前阶段为拆分实现任务，尚未开始实现。

任务清单见 [开发任务清单](tasks.md)。

## 已明确的需求

- 应用位于 `bl-zhipin/` 目录。
- 后端使用 Python 编写 API 接口。
- 前端使用 HTML，通过 API 与后端交互。
- 数据使用本地 SQLite 数据库存储。
- 注册时选择公司账号或求职者账号。
- 公司注册必须填写公司名称；每家公司只能拥有一个账号。
- 管理员可以在后台添加岗位名称。
- 公司账号可以发布招聘需求，内容包括岗位名称、岗位介绍和邮箱。
- 求职者账号不能发布招聘需求，可以向公司投递简历。

## 第一轮已确认的规则

用户确认时间：2026-10-27；答复为“全部按照推荐的来”。

1. **平台内投递**：求职者上传简历，在招聘详情页点击投递；公司登录后查看投递、下载简历。招聘邮箱作为联系信息展示。第二轮将支持格式从 PDF 扩展为 PDF 或 Word。
2. **公司唯一性**：公司名称忽略首尾空格和英文字母大小写后必须唯一。公司注册后直接使用，第一版不审核公司资质，因此不能防止公司名称被冒用。
3. **账号体系**：使用唯一用户名和密码登录。注册后角色固定。管理员通过初始化命令创建，公开注册仅允许公司账号或求职者账号。
4. **岗位目录**：管理员维护统一岗位名称目录。公司从目录选择岗位，再填写本公司的岗位介绍和联系邮箱；多家公司可以使用同一个岗位名称。
5. **本地运行**：启动一个 Python 服务，同时提供 HTML 页面和 API。通过浏览器访问，数据存储于本地 SQLite 文件。

## 第二轮已确认的规则

用户确认时间：2026-10-27；用户补充 Word 简历与邀请预约需求，其余第二轮规则均采用推荐方案。

1. **招聘管理**：公司可以编辑、关闭、重新开放自己的招聘需求。关闭后停止接收投递，保留已有投递记录；第一版不提供删除。
2. **投递内容**：填写姓名、联系邮箱，手机号选填，上传不超过 10 MB 的 PDF 或 Word 简历。Word 格式按 `.doc`、`.docx` 支持。
3. **投递约束**：同一求职者对同一条招聘需求只能投递一次，提交后保留当时资料，第一版不提供修改或撤回。
4. **邀请预约**：公司可以向求职者发邀请链接；链接打开后显示 HTML 表单，必填姓名、手机号和预约时间。该功能纳入第一版，具体流程在第三轮确认。原 Q8 的投递状态方案需结合预约流程确定。
5. **访问权限**：访客可以浏览开放中的招聘信息和联系邮箱，登录后才能投递。公司只能查看投给自己的简历；求职者只能查看自己的投递；管理员只管理岗位目录，不查看简历。
6. **岗位维护**：岗位名称去除首尾空格、忽略英文大小写后不能重复。管理员可以新增、改名、停用；停用后不能用于新招聘，已有招聘和投递记录保留。岗位改名同步显示在关联招聘中。
7. **页面与检索**：中文、蓝白配色。提供招聘列表与详情、注册登录、求职者投递记录、公司招聘与简历管理、管理员岗位管理页面。招聘列表支持关键词搜索和岗位筛选。补充邀请预约表单和公司预约记录查看入口。

## 第三轮已确认的规则

用户确认时间：2026-10-27；答复为“全部按照推荐来”。

1. **邀请对象与发放**：邀请绑定一条已有投递，由接收该投递的公司生成。求职者可以在“我的投递”中查看链接，公司也可以复制链接自行发送。第一版不自动发送邮件或短信。
2. **预约时间**：求职者自行选择未来的日期和时间，提交后即预约成功，公司在后台查看。第一版不设置可预约时段，不限制同一时间的预约人数，由公司协调安排。
3. **链接访问**：使用随机凭证，打开邀请表单无需登录。
4. **链接生命周期**：生成后 7 天有效，成功提交后不能重复提交。公司可以撤销尚未使用的邀请，失效或撤销后可以重新生成。

## 最终验收清单（已确认）

以下条目汇总已确认的业务规则，并明确投递与邀请状态的展示方式。用户已确认基于此范围拆分任务清单。

### 账号与权限

- 可以注册求职者账号或公司账号，并使用用户名和密码登录、退出。
- 用户名唯一；公司名称按去除首尾空格、忽略英文字母大小写的规则唯一。
- 公司注册必须填写公司名称，角色注册后固定；重复注册时提示原因。
- 管理员通过初始化命令创建，只维护岗位目录。
- API 校验角色和资源归属：求职者不能发布招聘，公司不能获取其他公司的投递和简历，求职者不能读取他人的投递记录。

### 岗位与招聘

- 管理员可以新增、改名、停用岗位，岗位名称按去除首尾空格、忽略英文字母大小写的规则唯一。
- 公司从有效岗位目录中选择岗位，填写介绍和有效联系邮箱并发布。
- 公司可以编辑、关闭、重新开放自己的招聘需求；关闭后停止接收投递，保留历史记录。
- 停用岗位后不能用它发布新招聘，已有招聘和投递保留；岗位改名同步到关联招聘。
- 访客可以浏览开放中的招聘列表、详情和联系邮箱，并按关键词搜索、按岗位筛选。

### 简历与投递

- 求职者登录后，填写姓名、联系邮箱、选填手机号，上传不超过 10 MB 的 PDF、`.doc` 或 `.docx` 简历后投递。
- 同一求职者对同一招聘需求只能投递一次；不提供投递修改、撤回和已提交简历替换。
- 公司可以查看投给自己的资料并下载简历，求职者可以查看自己的投递历史。
- 投递状态展示为“已投递”或“已查看”；公司打开投递详情后标记为已查看。预约邀请使用单独的状态展示。

### 邀请与预约

- 公司针对收到的投递生成专属邀请，求职者可在自己的投递记录中打开，公司也可复制链接自行发送。
- 邀请链接使用随机凭证，无需登录，7 天有效；表单不公开展示求职者已有的个人资料或简历。
- 表单必填姓名、手机号和未来的预约日期时间；面向用户的时间统一使用北京时间（Asia/Shanghai）。
- 提交成功即预约成功，公司能查看预约姓名、手机号及时间，求职者能在相应投递中看到预约结果。
- 邀请状态单独展示“待预约”“已预约”“已失效”“已撤销”；已使用、已失效或已撤销的链接不能再次提交。
- 公司可撤销尚未使用的邀请；失效或撤销后可以重新生成。重发后的旧链接保持无效。
- 不提供邮件短信自动发送、预约审批、可约时段配置或时间冲突限制。

### 界面与本地运行

- 所有页面采用中文、蓝白配色，覆盖招聘浏览、注册登录、求职者投递记录、公司招聘管理、公司投递与预约管理、管理员岗位管理及邀请预约表单。
- 前端使用 HTML，通过 API 与 Python 后端交互；一个 Python 服务提供页面与 API。
- SQLite 数据库及上传简历保存在本地，重启服务后仍可读取。
- 提供中文安装、启动、管理员初始化说明，数据库和上传文件不提交至 Git。

### 验证场景

1. 管理员创建岗位，公司注册并发布招聘，访客能够检索和查看。
2. 求职者分别使用 PDF、Word 简历完成投递，公司能够查看和下载。
3. 重复用户名、重复公司名、重复岗位名、重复投递均被拒绝。
4. 未登录投递、求职者发布招聘、跨公司查看简历和管理邀请均被 API 拒绝。
5. 公司生成邀请，求职者在无需登录的表单中预约，公司能够看到结果。
6. 链接失效、撤销、使用后重提及重发后使用旧链接均被拒绝。
7. 无效邮箱、无效手机号、过去的预约时间、超限或不支持的简历文件得到明确提示。
8. 关闭招聘后不能投递；重新开放后恢复接收；岗位停用后已有记录仍可读取。
9. 重启服务后，账号、岗位、招聘、投递、简历和预约仍然存在。
