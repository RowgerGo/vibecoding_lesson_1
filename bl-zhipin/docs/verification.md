## 浏览器验收过程

使用 Google Chrome 访问本机 `127.0.0.1:8765`，数据保存在隔离目录 `/private/tmp/bl-zhipin-browser-20261027`。公司名称和求职者资料均为虚构验收样本，未写入项目默认 `data/`。

1. 管理员登录，在岗位目录页面创建“Python 开发工程师”。
2. 注册公司“蓝屿科技（验收示例）”，登录工作台，填写介绍和邮箱发布招聘。
3. 关闭招聘，页面显示“已关闭”、开放数量降为 0；重新开放后恢复为 1。
4. 注册求职者，在招聘详情填写姓名、邮箱、手机号，使用系统文件选择器上传真实 `resume.docx`。
5. 投递后跳转“我的投递”，显示简历文件名和“已投递”。
6. 公司在“收到的简历”打开详情，页面标记“已查看”，显示原始投递资料和私有下载入口。
7. 点击下载，通过系统保存对话框将附件保存到临时目录，并验证内容与上传文件完全一致。
8. 生成邀请，撤销，再重新生成；复制展示的专属 URL，退出账号后直接打开。
9. 在 390 × 844 手机视口填写姓名、手机号及 `2026-11-10 10:30`，无需登录提交成功。页面显示同一北京时间。
10. 刷新链接，显示“已预约”，不再出现可提交表单，也不展示既有预约的姓名和手机号。
11. 公司登录“预约安排”，看到预约姓名、手机号、岗位、`2026-11-10 10:30`；求职者登录“我的投递”，看到“已查看”和相同预约结果。
12. 实际重启服务后刷新投递记录，账号会话与业务数据仍然存在。
13. 首页输入无匹配关键词时显示空状态；输入 `Python` 并选择对应岗位，组合查询返回 1 条招聘。
14. 在桌面 1366 × 900 和手机 390 × 844 视口检查页面；手机首页、公司工作台、邀请表单的页面宽度均未超出 390 像素，表格内容在自身容器内横向滚动。
15. 在隔离数据库中使公司测试会话失效，提交已填写的招聘表单；页面提示“请先登录”，保留表单内容，并恢复导航中的登录入口。
16. 停止验收服务后，在已加载的页面触发 API 操作，页面显示“网络连接失败，请检查服务是否运行后重试”。验收完成后恢复浏览器默认视口，关闭验收页，停止自建服务。

浏览器实际下载的 DOCX 样本 SHA256：

```text
99717d91dad6a60cf9aace0ba75556759eec468da99e690cc676687019681ea5
```

Chrome 扩展最初未开放文件 URL 权限，扩展上传入口无法使用；最终通过正常系统文件选择器完成上传，未修改浏览器扩展权限。附件下载最初等待系统保存对话框，完成正常保存后验证了文件内容。

浏览器验收发现并修复了登录表单多余隐藏字段导致的 422 错误、单条招聘卡片被网格拉伸，以及会话过期后未恢复登录入口的问题；修复后分别通过真实页面操作复验。
